**Status:** v0.5 H1 (Contract Foundation) — 2026-05-19
**Scope:** DB dialect 어댑터 (Stage 2 = `andrej-karpathy-rdb-ddl`)
**Reference impls:** `postgres`, `hsqldb` (둘 다 v0.4.x 시점 production)

## 1. 목적

새 DB 엔진 (MySQL, Oracle, SQLServer, SQLite …) 을 추가할 때 **계약을 만족하는 `Dialect` 인스턴스 + 5개 Jinja 템플릿** 만 등록하면 Stage 2 가 동작해야 한다. dialect-aware 로직이 코드 본체에 흩어지면 안 된다 (idempotent_insert 분기, 정규식 연산자 차이 등이 이미 발생한 적 있음).

---

## 2. 어댑터 슬롯 — `Dialect` 데이터 클래스

위치: `andrej-karpathy-rdb-ddl/scripts/dialect.py`

```python
@dataclass
class Dialect:
    name: str                       # 식별자, --dialect 플래그 값과 1:1
    template_dir: str               # 템플릿 디렉터리 (= name 권장)
    schema_strategy: str            # "native" | "prefix"
    type_map: Dict[str, str]        # 9개 논리타입 → 엔진 SQL 타입
    idempotent_insert: str          # seed.sql 의 충돌 회피 구문
    regex_op: Optional[str]         # 정규식 비교 연산자, 미지원이면 None
```

### 2.1 `schema_strategy`

| 값 | 의미 | 사용 시점 |
|:-:|:-:|:-:|
| `native` | 엔진이 `CREATE SCHEMA <name>` 지원 | postgres, hsqldb, mysql(8+), oracle |
| `prefix` | 스키마 미지원 — 테이블명에 `<schema>_` prefix | sqlite |

`prefix` 사용 어댑터는 템플릿이 `{% if schema_strategy == 'prefix' %}` 로 분기해야 한다 (현재 reference impl 들은 모두 `native` — `prefix` 첫 사용자가 분기 추가).

### 2.2 `type_map` — **필수 키 9개**

`bigserial`, `bigint`, `integer`, `varchar`, `text`, `boolean`, `timestamp`, `date`, `numeric`

키 누락 시 Stage 2 `revalidate` 가 명시적 에러. 어댑터가 엔진 네이티브 타입으로 매핑:

- `bigserial` 은 "PK auto-increment" 의 추상 — postgres → `BIGSERIAL`, hsqldb → `BIGINT GENERATED BY DEFAULT AS IDENTITY`, mysql → `BIGINT AUTO_INCREMENT`
- `text` 는 unlimited string — postgres `TEXT`, hsqldb `LONGVARCHAR`, mysql `TEXT`

### 2.3 `idempotent_insert`

`seed.sql.j2` 가 `{{ idempotent_insert }}` 자리에 그대로 삽입.

| 엔진 | 권장 값 |
|:-:|:-|
| postgres | `ON CONFLICT DO NOTHING` |
| hsqldb | `MERGE` (별도 MERGE 문 사용 시 빈 문자열 가능) |
| mysql | `INSERT IGNORE` 또는 `ON DUPLICATE KEY UPDATE id=id` |
| oracle | `MERGE INTO ... WHEN NOT MATCHED THEN INSERT` |

### 2.4 `regex_op`

엔진의 infix 정규식 연산자. `None` 이면 v005 (regex check) 룰이 silent-skip 되거나 `LIKE` fallback 으로 degrade (어댑터가 명시).

## 3. 템플릿 슬롯 — 5종 필수

위치: `andrej-karpathy-rdb-ddl/.claude/skills/karpathy-rdb-ddl/templates/<template_dir>/`

| 파일 | 역할 | 입력 컨텍스트 |
|:-:|:-:|:-:|
| `schema.sql.j2` | `CREATE SCHEMA` (또는 prefix 분기) | `domain`, `schema_strategy` |
| `tables.sql.j2` | `CREATE TABLE` + 컬럼 + PK | `entity`, `type_map` |
| `constraints.sql.j2` | FK · UNIQUE · CHECK | `entity`, `regex_op` |
| `indexes.sql.j2` | `CREATE INDEX` | `entity` |
| `seed.sql.j2` | `INSERT` (idempotent) | `entity`, `idempotent_insert` |

파일명·확장자 모두 고정. `ddl_gen.py` 가 이 5개를 순서대로 부른다.

## 4. 어댑터 등록 절차

1. `dialect.py` 에 `MYSQL = Dialect(name="mysql", ...)` 추가
2. `_REGISTRY` 에 `"mysql": MYSQL` 등록
3. `templates/mysql/` 디렉터리에 5개 .j2 작성
4. `ddl_compile.py --dialect mysql` 의 `choices` 에 추가
5. `tests/test_dialect_<name>.py` 작성 (아래 §6 참조)

## 6. 어댑터별 회귀 테스트 의무

| 테스트 | 목적 | 통과 기준 |
|:-:|:-:|:-:|
| `test_dialect_<name>_type_map.py` | 9 키 모두 존재 | KeyError 0 |
| `test_dialect_<name>_render.py` | 5 템플릿이 sample blueprint 로 렌더 가능 | TemplateNotFound 0 |
| `test_dialect_<name>_golden.py` | 표준 `customer` blueprint → 골든 SQL byte-exact | diff 0 |
| (옵션) `test_dialect_<name>_inDB.py` | 엔진 자체에 실 적재 | embedded mode 가능 시만 |

골든 fixture 는 `tests/golden/fixtures/dialect/<name>/` 하위에 저장.

## 7. Karpathy 정신 가드레일

- **단방향 컴파일러 유지**: 어댑터는 `blueprint → SQL` 변환만 수행. 런타임 상태/세션/캐시 없음.
- **파일 기반**: 모든 입출력 파일. 등록 외에 Python 임포트 측 사이드이펙트 금지.
- **누적 무관**: 어댑터 추가는 catalog/preset 누적 메커니즘에 영향 없음 (직교).
- **idempotent**: 같은 blueprint 두 번 컴파일 → 동일 byte 출력 (Stage 2 골든 테스트가 강제).

---

## 8. 계약 위반 시그널

다음이 관찰되면 어댑터가 계약 위반이므로 PR reject:

1. `type_map` 9 키 미만 → `test_dialect_<name>_type_map.py` 실패
2. 5 템플릿 미만 → 렌더 에러 (`TemplateNotFound`)
3. dialect 코드가 `dialect.py` 밖에 위치 → import 그래프 검사 실패
4. 같은 blueprint 의 두 번 컴파일이 byte-diverge → idempotency 위반
5. `--dialect <new>` 가 `ddl_compile.py choices` 미등재 → CLI 거부
