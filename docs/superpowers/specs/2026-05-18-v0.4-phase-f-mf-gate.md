## 의도와 어긋난 부분 명시

- **dsSample 9-col schema 외부 의존** — 본 Phase 는 `/nexacro-fullstack-starter` v0.8.2 의 frameLogin 구조를 표준으로 가정. starter 가 컬럼을 바꾸면 SchemaMismatch 가 즉시 발생하고 menu 단계만 skip 되므로 다른 단계는 영향 없음 — 하지만 사용자 수동 매핑이 필요. 향후 column-mapping 을 `.scaffold/menu-mapping.yaml` 로 외부화하면 starter 진화에 따라가기 쉬워짐. v0.4.2 후보.
- **Java package destination 하드코딩** — `com.nexacro.uiadapter.<slug>` 이 starter 표준이므로 합리적이지만 다른 starter (e.g., 사내 별도 base) 사용 시 customizable 필요. 현재는 CLI 플래그로 노출 안 됨. 우회: starter fork 후 동일 패키지로 통일.
- **Idempotency 보장은 단위 + E2E 테스트 수준** — 같은 target 에 N 회 overlay 해도 `.bak` 와 row/Service 가 증가하지 않음을 검증함. 그러나 사용자가 중간에 frameLogin 을 수동 편집한 후 다시 overlay 하면 `_safe_backup` 이 기존 `.bak` 을 보존 (덮어쓰지 않음) → 원본 상태 손실 가능. 사용자가 `.bak` 정리를 명시적으로 제어해야 함 (USER-GUIDE §5.5 안내됨).
- **`--target-project` 절대경로/상대경로 혼합 시** — orchestrator 에서 `pathlib.Path(...).resolve()` 호출하므로 일관됨. 단 Windows + WSL 경로 혼용 시 별도 테스트 없음.
- **실 target 통합 테스트 (Case 6) optional** — `D:\AI\testspace\nexa-boot-jdk17` 존재 시에만 활성. CI 환경에 없으면 module-level skip 으로 그린 유지. 회귀 안전망 약간 약화되지만 fixture-based Case 2~5 가 동일 코드 경로 커버.

기타 어긋남: **없음**.
