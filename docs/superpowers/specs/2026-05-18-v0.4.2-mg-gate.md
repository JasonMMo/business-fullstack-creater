## 어긋남 / 잔여 리스크

1. **`domain_slug` 필드 자체의 모호성** — `ScaffoldArgs.domain_slug` 는 여전히 존재하며 Stage 1-4 일부에서 사용된다. Stage 5 만 `--package` 마지막 segment 로 override 하는 비대칭이 남음. 이상적으로는 `_run_stage1..4` 도 같은 override 를 받아야 하지만, Stage 3/4 가 이미 `--package` 를 직접 쓰기 때문에 실제 산출물엔 영향 없다 (golden E2E 가 이를 회귀로 보호).
2. **`derive_slug` 자체 수정 보류** — Korean → 음역 변환 같은 본격적 슬러그화는 별도 의사결정 필요 (i18n / 사용자 prefs). 현 보완은 silent fail → loud warn 으로 충분히 안전.
3. **`source_pkg_prefix` 도출 단순성** — `--package com.foo.bar.shop` → `com.foo.bar` 는 `split(".")[:-1]` 단순 도출. 만약 사용자가 `--package shop` 한 segment 만 주면 source prefix 가 빈 문자열 → fallback `"com.example"` 사용. CLI 가 `--package` 에 최소 1 개의 `.` 을 요구하는 검증은 없음. 운영 상 거의 발생하지 않으나 후속 lint 후보.
