## 어긋남 / 잔여 리스크

1. **계약이 실증되지 않음** — 3 contract 모두 reference impl 만으로 정리됨. 새 어댑터 (MySQL/jakarta/React) 등록 과정에서 "암묵적 가정" 이 드러날 가능성 농후. H2~H4 가 본 계약을 **환류 (feedback)** 시키도록 명시되어 있으나, 실제 진행 시 계약 minor bump 가 1~2 회 필요할 것으로 예상.
2. **service-contract 의 suffix 규칙은 아직 v2 가 아님** — 현재 `codegen.py:32` 가 `.vanilla` 만 하드코딩. H3 에서 일반화 (`f".{lane}"`) 까지 가야 계약 v2 완료. H1 은 그 plan 만 박아둠.
3. **ui-contract 의 `UIOverlayAdapter` Protocol 은 미실증 인터페이스** — 현재 `stage5_overlay.py` 는 nexacro 하드코딩. H4 에서 분할까지 가야 계약이 실제로 작동. 계약 §5.3 의 Protocol 시그니처가 H4 작업 중 변경될 가능성 있음.
4. **`--ui` CLI 플래그 미도입** — ui-contract 가 향후 도입 예정으로 명시했으나 현재 scaffold_cli.py 는 `--lane` 만 있음. H4 에서 추가 필요.
5. **MySQL/React/Vue 의 "잠재 발견"** — 본 contract 들은 reference impl (postgres/nexacro/vanilla) 의 일반화에서 추론되었지만, 새 어댑터의 진짜 요구사항 (예: MySQL 의 `utf8mb4` charset 문제, React 의 Suspense 경계) 는 H2~H4 에서만 드러남.
