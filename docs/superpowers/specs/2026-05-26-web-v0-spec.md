# Web v0 Spec — business-fullstack-creater Static Asset Portal

**Date:** 2026-05-26  
**Growth context:** Web v0 (new exposure channel alongside CLI + Markdown)  
**Status:** LOCKED — implementation only, no redesign

---

## 1. Goal & Non-Goals

**Goal.** Provide a pre-generated, fully static HTML portal hosted under `docs/` (GitHub Pages
compatible) that exposes the same compounding asset base already visible via the CLI (`/orient`,
`/list-domains`, `/diagnose`) and Markdown (`learn-log.md`, `docs/USER-GUIDE.md`) to users who
prefer a browser view. The portal shows a tile grid of all verified domains on the landing page
and a per-domain detail page with layer selector, preview pane (DDL · Mapper · Controller · Service
tabs), and a "Try it" zip-download + run-snippet panel. All content is produced at build time by a
single Python generator (`scripts/workflow/web_index.py`) that reuses existing `list_domains.py`
and `learn-log.md §1` data — no new data sources are introduced.

**Non-Goals.** Live execution of any scaffold command is explicitly out of scope for v0. There is
no backend service, no server-side rendering, no authentication, no per-user state, and no
real-time dashboard. The portal does not replace the CLI; it mirrors a snapshot of already-verified
assets. i18n (Korean-first matching `learn-log.md`) is deferred. The L4 live sandbox
(GitHub Codespaces deep-link) is deferred to v1+.

## 2. Output Directory Contract

All generated output lives under `docs/`. The generator MUST NOT touch any pre-existing file or
directory not listed as "generated" below.

```
docs/
├── index.html                          (generated, overwrite OK each run)
├── domain/
│   └── <slug>.html                     (generated per domain, overwrite OK)
├── scaffolds/
│   └── <domain-slug>/
│       ├── jakarta/
│       │   ├── DDL.sql                 (generated — source preview file)
│       │   ├── Mapper.xml              (generated — source preview file)
│       │   ├── Controller.java         (generated — source preview file)
│       │   ├── Service.java            (generated — source preview file)
│       │   └── project.zip             (generated — downloadable archive)
│       ├── javax/                      (same structure; present only for verified lanes)
│       ├── vanilla/                    (same structure; present only for verified lanes)
│       └── nexacro/                    (same structure; present only for verified lanes)
├── assets/
│   ├── style.css                       (generated, overwrite OK)
│   └── preview.js                      (generated, overwrite OK)
├── superpowers/                        (PRE-EXISTING — never touch)
└── USER-GUIDE.md                       (PRE-EXISTING — never touch)
```

**Notes:**
- `docs/domain/` and `docs/scaffolds/` directories are created by the generator if absent.
- Preview source files (`DDL.sql`, `Mapper.xml`, `Controller.java`, `Service.java`) are
  extracted from the existing Stage 2/3 scaffold output directories by `discover_scaffold()`
  in `scripts/workflow/live_overlay.py`. If a file cannot be found, the preview slot renders
  an inline `<!-- not available -->` comment — the page is still generated.
- `project.zip` contains the full scaffold tree for that domain+lane combination. The generator
  creates it from the same source directories via `zipfile.ZipFile`.
- Subdirectory depth under `docs/scaffolds/` is `<domain-slug>/<lane>/` — two levels, no deeper.

## 3. `web_index.py` CLI Contract

**Module path:** `scripts/workflow/web_index.py`  
**Invocation:** `python -m scripts.workflow.web_index [flags]`  
**Also supports:** `python scripts/workflow/web_index.py [flags]`

### Signature

```python
def build(
    domains: list[str] | None = None,   # None = all domains from list_domains.py
    check_only: bool = False,           # True = verify outputs exist; no writes
    json_output: bool = False,          # True = emit JSON report to stdout
    docs_root: Path = DOCS_ROOT,        # override for tests
) -> BuildResult:
    ...
```

### Flags

| Flag | Effect |
|---|---|
| *(no flags)* | Full rebuild — all domains, all verified lanes |
| `--domain <slug>` | Rebuild one domain only (slug must match a `Domain.name` from `load_domains()`) |
| `--check` | Verify every expected output file exists; print missing list; no writes |
| `--json` | Emit a JSON `BuildResult` dict to stdout instead of human-readable table |

### Exit Codes

| Code | Meaning |
|---|---|
| `0` | Success — all outputs written (or all exist in `--check` mode) |
| `1` | Partial failure — at least one domain/lane could not be generated; others succeeded |
| `2` | Bad arguments (unknown flag, bad slug, conflicting options) |

### `BuildResult` dataclass

```python
@dataclass
class BuildResult:
    domains_ok: list[str]       # slugs successfully built
    domains_failed: list[str]   # slugs that encountered errors
    missing_files: list[str]    # relative paths missing (--check mode only)
    warnings: list[str]         # non-fatal notes (e.g. preview file not found)
```

## 4. Matrix Data Structure

The pre-gen matrix drives which `docs/scaffolds/<slug>/<lane>/` directories are created and which
status chips appear on tiles.

```python
from __future__ import annotations
from dataclasses import dataclass


@dataclass(frozen=True)
class MatrixEntry:
    domain: str    # ASCII slug matching Domain.name from list_domains.load_domains()
    lane: str      # "jakarta" | "javax" | "vanilla" | "nexacro"
    status: str    # "verified" | "default-unverified"
    source: str    # human-readable provenance, e.g. "learn-log §1 row 1" or "jakarta-default"
```

### Status Values

- `"verified"` — lane has passed L4 live WAS smoke for this domain (sourced from
  `learn-log.md §1` table rows).
- `"default-unverified"` — lane is added by default (every domain gets `jakarta` at minimum)
  but has not yet been L4-verified. Badge style differs from verified.

### Builder Function

```python
def build_matrix(
    domains: list[Domain],              # from scripts.workflow.list_domains.load_domains()
    learn_log_path: Path = LEARN_LOG,   # defaults to CREATER_ROOT / "learn-log.md"
) -> list[MatrixEntry]:
    """Return MatrixEntry list for all (domain, lane) pairs.

    Algorithm:
    1. Parse learn-log.md §1 table to extract (domain_slug, lane, growth_ref) triples
       marked with ✅ — these become status="verified".
    2. For every domain in `domains`, ensure a jakarta entry exists; if not already
       present from step 1, add status="default-unverified", source="jakarta-default".
    3. Return sorted by (domain, lane).
    """
```

## 6. CSS Approach

A single `docs/assets/style.css` file, no CSS framework, no preprocessor. Custom properties
define the full color palette and spacing scale at `:root` (light theme only for v0; dark-mode
and theme switching are deferred to v1). The domain tile grid uses CSS Grid with
`grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))` for responsive layout without
media-query breakpoints. The tab bar and lane radios use standard flex layout. The `chip-row`
uses inline-flex. Status chip colors (`--chip-verified`, `--chip-unverified`) are the only
semantic color tokens beyond the base palette. Total budget: ~120 lines.

---

## 7. JS Approach

A single `docs/assets/preview.js` file, vanilla ES2020, no framework, no build step. The script
handles exactly three behaviors: (1) **tab switching** — clicking a `[role=tab]` button shows
the matching `[data-tab]` preview block and hides others; (2) **lane radio change** — when the
`<input[name=lane]>` selection changes, the visible preview blocks are filtered to only show the
selected lane, and the download link `href` is updated to point at the new lane's `project.zip`;
(3) **copy-to-clipboard** — clicking `.copy-btn` reads the text of `[data-target]` and calls
`navigator.clipboard.writeText()`, toggling a "Copied!" label for 1.5 s. No global state beyond
DOM event listeners; all data lives in `data-*` attributes on the HTML elements. Target budget:
50–100 LoC.

## 8. `/contribute-back` Integration

`scripts/workflow/contribute_back.py` already has a `run()` function that (a) scans 5 repos for
git changes since the last Growth start date, (b) groups them by category, and (c) walks the user
through a checklist of backflow questions. The web integration adds one step at the **end** of
`run()`, after the existing checklist loop:

```python
# --- web_index rebuild (Phase A5 hook) ---
try:
    from scripts.workflow import web_index as _wi
    result = _wi.build(json_output=False)
    if result.domains_failed:
        print(f"[contribute-back] web_index partial failure: {result.domains_failed}",
              file=sys.stderr)
    else:
        print(f"[contribute-back] web_index rebuilt OK "
              f"({len(result.domains_ok)} domains)")
except Exception as exc:  # never block the checklist on web errors
    print(f"[contribute-back] web_index skip (error: {exc})", file=sys.stderr)
```

This call is **non-blocking**: any exception from `web_index.build()` is caught and printed as a
warning; `contribute_back.run()` always returns `0` on its own success regardless. The web rebuild
is intentionally placed after the learn-log checklist so that the freshly confirmed backflow data
is already written before the HTML is regenerated.

The `web_index` module must NOT import from `contribute_back` — the dependency is one-way:
`contribute_back` → `web_index`.

## 10. Out of Scope for v0 (Deferred to v1+)

The following items are explicitly excluded from this spec. Implementations MUST NOT add them.

- **L4 live sandbox.** No in-browser execution, no container spin-up. The recommended v1 approach
  is a GitHub Codespaces deep-link: a `docs/domain/<slug>.html` "Open in Codespaces" button that
  encodes the scaffold parameters as URL query-string and triggers a devcontainer that runs
  `python scripts/scaffold_cli.py` automatically. Spec and implementation deferred to v1.
- **i18n / Korean-first UI.** All portal text is English for v0. Korean domain names are
  displayed as-is (UTF-8) in tile headings, but UI chrome is English. A `lang="ko"` attribute
  is used at the `<html>` level for correct font rendering; no translation system is introduced.
- **Authentication / per-user state.** The portal is entirely public and stateless.
- **Server-side anything.** No Node.js server, no Python WSGI, no API endpoints. Every file
  served by a plain HTTP static server (e.g. `python -m http.server` or GitHub Pages).
- **Dark mode / theme switching.** Light theme only for v0.
- **Real-time scaffold execution.** The "Try it" panel provides a zip download and a copy-paste
  shell snippet only. No WebSocket, no subprocess invocation from the browser.
- **Search / filtering on the landing page.** Tile grid is unfiltered for v0.
- **Automated CI publish.** No GitHub Actions workflow for auto-deploying to GitHub Pages.
  Manual `python -m scripts.workflow.web_index && git push` is sufficient for v0.
